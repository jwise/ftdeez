# `ftdeez`: FTD2xx emulation, easy

`ftdeez` is a wild hack that emulates a FTD2xx-like device (usually, a
FT2232H or FT4232H) by exposing a virtual USB/IP device.  With
`ftdeez_glasgow`, it uses an attached [Glasgow Interface
Explorer](https://glasgow-embedded.org/latest/intro.html) to emulate a UART
and the MPSSE engine on the Glasgow's FPGA, allowing limited compatibility
with existing FTD2xx client software (like the popular `pyftdi` library)

`ftdeez` can emulate even more channels than a genuine FTDI device has, and
with any combination of pin assignments available on the Glasgow hardware,
and with any I/O voltage that the Glasgow hardware can generate internally.
(Traditional FTDI devices like Tigard have fixed-direction level shifters,
so a device wired for UART is not also usable for SPI, because the
Glaswegians at Future Technologies are insane and bind the I/O pins
differently for UART mode vs. MPSSE mode.)

To try `ftdeez_glasgow` out, connect a Glasgow, and connect 3.3V peripherals
to `{tx,rx}` = `{A0,A1}` and `{tx,rx}` = `{B0,B1}`.  (Or cross-connect it
externally).  Then try:

```
$ python3 ftdeez_glasgow.py --channel=A0,A1 --channel=B0,B1 --voltage-a 3.3 --voltage-b 3.3
```

And in another window:

```
# modprobe vhci_hcd
# usbip attach -r 127.0.0.1 -d 1-1
$ lsusb
$ picocom /dev/ttyusb0
```

Or, if you have some I2C peripherals, you can try a more advanced usage:

```
$ python3 ftdeez_glasgow.py --channel A6=pu,A7=pu,A7=i+pu
```

This configures pin A6 as the I2C SCK pin, or the MPSSE TCK pin (with a
pullup); pin A7 as the I2C SDA pin, or the MPSSE TDI pin (output from
MPSSE); and pin A7 internally connected also as the MPSSE TDO pin (input to
MPSSE), but connected only as an input, all with a pullup attached.  You can
then attach it with the above `usbip attach` command,

From there, try attaching a NeoKey 1x4 device, and running `python3
test/pyftdi-i2c.py`.

## Where is the code?

* `pyusbip.py` is a version of pyusbip that has been modified to be able to
  talk to a `libusb1` other than the system-native one, and to be called
  from other loops.

* `fakeusb1.py` is a fake `usb1` Python library, that exports a fake
  `USBContext`, and provides a wrapper for a base emulated USB device.

* `ftdeez.py` implements a stub D2xx-like device on top of `fakeusb1` that
   takes stub D2xx channels, and routes USB requests to the D2xx channels.

* `ftdeez_glasgow.py` fills in the D2xx channel stub with a `GlasgowD2xxChannel`
  implementation that wraps stream and register interfaces to Glasgow
  gateware, which is implemented in `GlasgowD2xxComponent`.  It also
  implements a `UartTx` and `UartRx` to abstract over those in Glasgow
  itself, which are not meant to be embedded into other modules.

* `mpsse.py` is an Amaranth implementation of the MPSSE state machine, and
  some tests for it.  It is instantiated inside the `GlasgowD2xxComponent`.
